# IC Wire scope and decisions

> Historical findings only. Raw measurements, snapshots, logs and build artifacts
> were retired from this tree. A summary/hash cannot verify missing payloads.
> Use the maintained development commands for fresh measurements.

IC Wire provides one selected Postcard encoding for controlled Rust endpoints.
Consumers select stable method identities explicitly or through the endpoint
integration's exported-name hash; fields and variants follow Serde order.
The [runtime guide](runtime.md) specifies the maintained bytes, supported types,
primitive validation, resource limits and typed errors.

## Ownership

| Owner | Responsibility |
| --- | --- |
| IC Wire | Encoding, bounds, derives, typed codec errors and TypeScript codecs |
| IC Wire Endpoint group | Typed handlers and their proc-macro generator connected to Platform through native Wire frames |
| IC Wire optional platform-types feature | Host schemas for Platform's owned Principal/Account; Platform Types retains Serde ownership |
| IC Platform Runtime | IC exports, query/update contexts and executor |
| Consumer contract | Request/reply types, method identities and semantic validation |
| Application/framework owner | Authentication, dispatch policy and final artifact admission |
| Delivery owner | Retry decisions, exact retained bytes and effect recovery |
| Database owner | Storage layouts, ordered keys and persistence semantics |
| IC Build | Compiler-diagnostic execution for the private qualification fixture |
| Shared Tooling | Reviewed contributor setup, formatting and release mechanics |

The core codec remains Wasm-safe and independent of platform and host tooling.
Its schema derive is optional: `typescript` selects `ic-wire-derive`, including
through `platform-types` or Endpoint schema forwarding. Runtime Serde codecs
do not require Wire metadata or the metadata proc macro.
The independent `platform-types` feature selects only `ic-platform-types` and
host schema support. The independent `ic-wire-endpoint` package selects independent Platform Runtime
CDK and uses its generator and executor. Its exactly versioned
`ic-wire-endpoint-macros` package owns query/update expansion. Core
`ic-wire-derive` owns only schema metadata. Core/derive and endpoint release groups
can evolve separately; one codec and one schema trait remain.
See [typed endpoints](endpoints.md). Browser transports remain consumer-owned. The unpublished
benchmark crate may use Candid and PocketIC as dev dependencies for codec
comparisons and IC instruction measurements. The standalone endpoint fixture also
uses Platform/Testkit for installed qualification. Published runtime graphs retain
no Candid or simulator dependencies.

## Contract discipline

[Generated contract fingerprints](evidence/contract-fingerprint.md)
are under investigation as a replacement for hand-managed identities. The
host-only prototype reuses the existing eight-byte field and leaves the codec
unchanged; no production default or public fingerprint API is adopted. Its
schema-freshness workflow, recursive/custom-layout policy and stable input format
must be qualified before activation.

The [prepared macro integration](evidence/contract-artifact.md) removes
manual `id` options in an isolated source, supplies generated keys from a checked
host artifact and refuses stale/incomplete inputs. It adds no Wasm bytes over the
preceding fingerprint prototype and preserves its measured runtime costs, but
repeated source verification is a host regression. Consumer build ownership,
recursive projection, diagnostics and a stable format remain before activation.
Current production attributes and framing are unchanged.

Check lengths and budgets before allocation, reject malformed/trailing input
with typed errors. Preserve original frame bytes for hashing and same-release
retries; decoding does not guarantee byte-identical reserialization. Serde projection follows declaration order without field IDs;
field/variant reordering changes that protocol and requires
coordinated consumers.
Consumers retain their own hash domains, semantic ordering and retained-byte
obligations. The pre-1.0 contract has one current layout, without fallback readers,
automatic migration or parallel compatibility lanes.

Qualification covers codec behavior and generated byte conformance. Production
endpoint integration and installed performance require evidence at their consumer.

The production codec uses Serialize/Deserialize and runtime resource admission.
Wire supplies host-only metadata, including concrete generic types. The
serializer-generating Wire derive, static shape admission and typed method codec
are retired; Wire now names the metadata-only derive.
Bounded owned/borrowed field wrappers share Serde representations; borrowing
changes custody, not framing. Alternative serializers remain research only.

## Host schema traversal

Host work allowances have separate owners because references cost differently:

| Traversal | Allowance and scope |
| --- | --- |
| Inline `native_schema` | 65,536 `describe` visits, depth below 64 |
| `SchemaRegistry` collection | 65,536 visits/registrations/collision rechecks across the collector, depth below 64 |
| Registry finish validation | Fresh 65,536 metadata nodes; named references are leaves |
| Bulk pre-validation | Fresh 65,536 metadata nodes across definitions and explicit roots; references are leaves |
| Rooted bulk lint | 65,536 expanded visits per root, 1,000,000 across the report; depth below 64 |
| Metadata generation/validation | Fresh 65,536 nodes across definitions and method/payload roots; references are leaves |

Metadata validation retains its existing inline depth boundary of 64. Only rooted
lint expands named references at each use site, stopping an active recursive
reference without suppressing sibling paths. Its former aggregate 65,536 limit
refused large ordinary compositions; the larger report allowance admits those
while the per-root ceiling rejects explosive DAGs. Exhaustion returns typed
`Complexity`, with no partial diagnostic callback or silently omitted paths.
The complete report remains available; Display prints at most eight diagnostics
plus an omission count. Visit ceilings bound expansion/cardinality, not exact
host heap use or arbitrary trusted metadata/callback allocations. There is no
change to runtime limits, wire acceptance, bytes, field order or method IDs.

## Field selection

New contracts should use byte-oriented fields for binary data and `Packed<T>`
for large homogeneous arrays of its supported integers or 32-byte hashes.
These fields expose contiguous data to the existing Serde byte-buffer path.
Use ordinary collections for records, general shapes and small integers where
varint compactness is the priority. This is a declaration convention, not an
automatic rewrite by the metadata derive or serializer.

Keep field-specific limits when selecting a representation. `PackedI16<N>`
retains an element bound; `Packed<T>` relies on operation budgets and consumer
validation. Apply the [field adoption procedure](packed-fields.md#adopting-an-existing-field)
when changing an existing declaration, including TypeScript shapes and retries.
