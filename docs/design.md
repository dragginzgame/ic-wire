# IC Wire scope and decisions

IC Wire provides one selected Postcard encoding for controlled Rust endpoints.
Shared contracts declare stable field/variant identities and method bindings.
The [runtime guide](runtime.md) specifies the maintained bytes, supported types,
canonicality, resource limits and typed errors.

## Ownership

| Owner | Responsibility |
| --- | --- |
| IC Wire | Encoding, bounds, derives, typed codec errors and TypeScript codecs |
| Consumer contract | Request/reply types, method identities and semantic validation |
| Endpoint owner | Transport, authentication, dispatch, rollback and exports |
| Delivery owner | Retry decisions, exact retained bytes and effect recovery |
| Database owner | Storage layouts, ordered keys and persistence semantics |
| IC Build | Compiler-diagnostic execution for the private qualification fixture |
| Shared Tooling | Reviewed contributor setup, formatting and release mechanics |

The runtime remains Wasm-safe and independent of platform and host tooling.
No endpoint SDK, simulator or browser transport is part of the workspace.
All dependency roles, including tests, use the selected codec boundary.

## Contract discipline

Check lengths and budgets before allocation, reject malformed/trailing input
with typed errors, and preserve canonical bytes for hashing and same-release
retries. Field and variant identity must not depend on Rust declaration order.
Consumers retain their own hash domains, semantic ordering and retained-byte
obligations. The pre-1.0 contract has one current layout, without fallback readers,
automatic migration or parallel compatibility lanes.

Qualification covers codec behavior and generated byte conformance. Production
endpoint integration and installed performance require evidence at their consumer.
