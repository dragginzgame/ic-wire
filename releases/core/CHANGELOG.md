# Core group changelog

Covers ic-wire and ic-wire-derive. Private qualification packages previously
shared this version series and now have an independent workspace. This independent
series begins at 0.12.0. Earlier coordinated releases end at 0.11.0 and remain
in [shared history](../history.md).

## [0.21.4] - 2026-11-12

### Performance

- Build decoded browser packed-boolean arrays with indexed writes after complete
  validation. Large-buffer Node decode improves 64–80% in repeated measurements,
  with control regressions documented. Regenerate clients; exact bytes, limits,
  malformed-input rejection and owned results are unchanged. No Wasm change.

- Decode browser collection lengths with the existing numeric u32 reader,
  avoiding BigInt conversions. Nested-list decoding improves in repeated Node
  measurements; flat-list and small-control regressions are recorded in the
  paired study. Regenerate clients; bytes, identities, limits and malformed-input
  acceptance remain unchanged. Rust runtime and Wasm are unchanged.

### Maintenance

- Deferred repository maintenance: fetch both root and qualification locks before
  offline hosted CI checks. Clean runners can now resolve the private benchmark
  dependencies during Core pin admission and benchmark validation. No public
  package or codec change is required.

## [0.21.2] - 2026-11-11

### Performance

- Borrow host advisory-lint names instead of allocating temporary strings for
  ordinary fields and recursion tracking. Matched large plain/shared-reference
  fixtures use 39%/65% fewer allocations; escaped-name timing has a small measured
  regression. Generated output, warning paths, codec bytes, identities, limits
  and acceptance are unchanged. No runtime Wasm saving is claimed.

- Append the serialized TypeScript registry directly to the generated module,
  avoiding a temporary full-registry copy. Large plain/shared-reference fixtures
  allocate 18%/20% fewer bytes; opt-3 timing regressions are recorded in the paired
  evidence. Generated bytes and runtime contracts remain unchanged.

- Write generated declarations directly into the TypeScript output and avoid a
  second registry buffer when prototype-key escaping is unnecessary. Paired
  large plain/shared-reference fixtures allocate 20.7%/17.2% fewer bytes;
  generation-time regressions are recorded. Generated output and runtime
  contracts remain unchanged.

- Render composite TypeScript types directly instead of allocating and joining
  field fragments. The large-record fixture uses 31.7% fewer allocations and
  32.3% fewer allocated bytes, with measured generation improvements in both
  profiles. Generated bytes, schema validation and runtime contracts are unchanged.

### Maintenance

- Adopt Toko Tooling 0.39.11 in both workspaces, including its reviewed dependency
  boundary correction and bounded LOC labels with an explicit wide report option.
  Preserve installed entrypoints and consumer-owned policy.

## [0.20.0] - 2026-11-10

### Changed

- Hard cut to upstream Postcard decoding; delete the private parser. Rust and
  generated browser readers now accept redundant varints within width bounds
  (`80 00` becomes zero); Rust also accepts `02 61 62` as char `'a'`.
  Browser Result tags also use u32 varints; collection lengths follow Wasm32
  (five groups), while upstream on a 64-bit host admits ten.
  Encoder bytes, framing, identities and budget rules stay unchanged. Regenerate
  clients, review strict-rejection assumptions and retain original retry/hash
  bytes. Existing stored encodings need no migration; no fallback reader remains.
  The matched 154-case fixture saves 287/247 uncompressed opt-z/opt-3 Wasm bytes.
  Retain measured opt-z decode regressions up to 11.1% (large byte-array batch:
  9.2%); 19 rows exceed the instruction screen. See the
  [hard-cut qualification](../../docs/benchmarks/candid-comparison.md#upstream-postcard-hard-cut--10-november-2026).

### ⚡ Performance

- Reuse the bounded u32 tag writer for newtype enum variants. The matched
  opt-z fixture saves 326 total Wasm bytes and cuts large result-map / mixed-enum
  encode instructions by 16.6% / 9.2%. Retain the explicit tradeoff: page encode
  regresses 1.9% / 5.4% at opt-z / opt-3; opt-3 adds 232 Wasm bytes and tiny
  result encoding adds 131 instructions. The strict opt-3 cost screen fails.
  Bytes, identities, limits and acceptance remain unchanged; no migration.
  See the [qualification](../../docs/evidence/encoder-followup.md#newtype-enum-tags--10-november-2026).
- Consolidate the encoder's depth admission into one shared check, preserving
  exact depth, node and allocation limits. The matched aggregate fixture saves
  796 uncompressed Wasm bytes at opt-z and 16 at opt-3; large page/map encodes
  improve modestly. Small instruction regressions remain below 0.6%.
- Reuse the optimized integer writer for unit enum tags. The matched mixed-enum
  batch uses 9.0% fewer opt-z encode instructions and saves 13 Wasm bytes;
  opt-3 saves 11 bytes with unchanged counters. Bytes, admission and acceptance
  remain unchanged; no consumer migration is needed.
- Check finite-f32 values in pairs within the existing shared scanner. In the
  matched 1 MiB fixture, opt-z encode/decode instructions fall 32.7%/11.6% for
  5 extra uncompressed Wasm bytes. Small controls improve and f64 is unchanged.
  Bytes, identities, limits and finite-only acceptance remain unchanged; no
  consumer migration is needed. See the [measurement](../../docs/evidence/primitive-bulk.md#paired-f32-validation--10-november-2026).

### 🧪 Testing
